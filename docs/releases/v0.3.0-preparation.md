## Review entry points / 审查入口

Start from the developer web instructions in both READMEs. Relevant sources:

| Area | Files | Review focus |
|---|---|---|
| Conversation and revisions | `detweave/conversation.py`, `detweave/server.py` | clarification preserves model; parent links; restore; cancellation; stale version conflicts; human confirmation |
| Model transport | `detweave/providers.py`, `detweave/streaming.py` | endpoint/authentication; parsing; incomplete streams; timeout/cancel; source evidence |
| Project directories | `detweave/projects.py`, `detweave/folder_picker.py` | location registry; permissions; atomic writes; preserved user files |
| Saved API settings | `detweave/settings.py`, `detweave/web/app.js` | plaintext local storage; restrictive permissions; no keys in project/export; profile isolation; save/restore races |
| Developer HTML | `detweave/dev_ui.py`, `detweave/web/` | local backend only; CSP; startup order; UI state; bilingual labels |
| Native wrappers | `packaging/src/detweave_native/`, `packaging/pyproject.toml` | per-platform paths, permissions, settings storage and file dialogs |

Review comments should include location, reproduction/impact and proposed correction.
Do not include credentials or private project content. Do not modify unrelated local
workspaces. The local untracked `AntiGravity-Argon/` is not part of this release change.

审查意见请包含代码位置、复现方法或实际影响、建议修正方式。收到意见后逐项处理并记录，
不能用旧版验证结果代替修正后版本的验证。

## Release changes / 发行内容

- Continuous design conversation, clarification and immutable geometry revisions.
- Version restoration, deterministic parameter differences and explicit human confirmation.
- Local Python-backed single HTML development environment; no hosted relay.
- Automatically saved provider/model/API configuration; separate from project data.
- Actionable local directory permission errors.

PDF design-report generation is not implemented. No standalone Python/WASM HTML
application will be restored as a release asset. Geant4/DD4hep runtime validation
remains separate from application/UI testing.

## Build gates / 构建门槛

1. Receive independent review, fix accepted findings and record remaining limitations.
2. Rerun Python and browser tests against the reviewed commit, then test real provider
   multi-turn behavior with an authorized key (never commit it).
3. Manually dispatch **Native build candidates** with `review_approved: true` on that
   exact commit/ref. Tag/branch pushes no longer trigger native compilation.
4. Manually dispatch **tests** with `build_distribution: true` to produce wheel/sdist.
   Ordinary push/PR jobs do not build these distribution archives.
5. Test each native candidate, verify versions and dependencies, then produce fresh
   SHA256SUMS and BUILD-MANIFEST describing actual results and signing status.
6. Only then create the v0.3.0 tag and GitHub Release with reviewed bilingual notes.

These inputs are explicit maintainer attestations, not automatic proof of code review.
The initial preparation commit used `[skip ci]`; review is now complete and
manual workflows have been dispatched with the maintainer authorization.

以上勾选项是维护者明确声明审查已完成，不是自动审查系统。审查修正完成后，
已按用户授权启动测试、编译与验证。
