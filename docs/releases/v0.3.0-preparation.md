## Planned changes / 拟发行内容

- Continuous design conversation, clarification and immutable geometry revisions.
- Version restoration, deterministic parameter differences and explicit human confirmation.
- Local Python-backed single HTML development environment; no hosted relay.
- Automatically saved provider/model/API configuration; separate from project data.
- Actionable local directory permission errors.

PDF design-report generation is not implemented. No standalone Python/WASM HTML
application will be restored as a release asset. Geant4/DD4hep runtime validation
remains separate from application/UI testing.

## Build gates / 构建门槛

1. Receive independent review, fix accepted findings and record remaining limitations.
2. Rerun Python and browser tests against the reviewed commit, then test real provider
   multi-turn behavior with an authorized key (never commit it).
3. Manually dispatch **Native build candidates** with `review_approved: true` on that
   exact commit/ref. Tag/branch pushes no longer trigger native compilation.
4. Manually dispatch **tests** with `build_distribution: true` to produce wheel/sdist.
   Ordinary push/PR jobs do not build these distribution archives.
5. Test each native candidate, verify versions and dependencies, then produce fresh
   SHA256SUMS and BUILD-MANIFEST describing actual results and signing status.
6. Only then create the v0.3.0 tag and GitHub Release with reviewed bilingual notes.

These inputs are explicit maintainer attestations, not automatic proof of code review.
This preparation commit uses `[skip ci]` to avoid starting builds/tests before review.
No workflow is dispatched during preparation; tests are run after review as requested.

以上勾选项是维护者明确声明审查已完成，不是自动审查系统。本轮准备提交跳过 CI；
接收审查意见、修正后再测试、编译、验证、发行。
